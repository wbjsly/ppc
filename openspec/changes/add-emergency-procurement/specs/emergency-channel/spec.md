# Spec Delta: emergency-channel

## Purpose
紧急通道台账：按登录用户账号的紧急采购通道状态（开通/阻断）、L1321 逾期自动阻断、总监复核恢复并关闭全部逾期例外、台账展示与留痕。

## ADDED Requirements

### Requirement: 通道状态语义（无行即开通）
通道台账按**登录用户账号**唯一（无采购员实体，账号即主体，偏差表记）。系统 MUST 以「无台账行 = 已开通（OPEN）」为隐式语义：申请人无 BLOCKED 记录即可发起紧急申请；`BLOCKED` 状态 MUST 阻断该账号发起新的紧急申请（L1321），阻断 MUST 记录原因（含来源 EA 单号）、时间、操作来源（系统自动）。

#### Scenario: 默认可发起
- **WHEN** 账号无任何台账行时发起紧急申请
- **THEN** 发起成功（隐式 OPEN）

#### Scenario: 阻断记录落台账
- **WHEN** 某 EA 逾期触发通道阻断
- **THEN** 台账出现该账号 BLOCKED 行，含阻断原因、时间

### Requirement: 总监复核恢复与例外关闭
对 `BLOCKED` 通道 MUST 提供**总监复核恢复**动作：必填复核说明（≥2 字）→ 状态恢复 OPEN（删除或覆盖 BLOCKED 行均可，恢复留痕：复核人/时间/说明），并 MUST 同步将该账号名下全部「逾期例外」状态的 EA 关闭（恢复路径闭环，L1321：补齐+总监复核通过后恢复权限并关闭例外——关闭动作记入 EA 状态迁移与事件）；对 OPEN 通道执行恢复 MUST 422（无需恢复）。复核恢复 MUST 要求 ROLE_ADMIN（403）。

#### Scenario: 恢复并关闭例外
- **WHEN** 对 BLOCKED 通道提交复核说明并恢复
- **THEN** 通道回到 OPEN，该账号全部「逾期例外」EA 迁移为已关闭，复核人/时间/说明留痕

#### Scenario: OPEN 通道拒绝恢复
- **WHEN** 对已 OPEN 的账号执行恢复
- **THEN** 系统 422 提示当前已是开通状态

### Requirement: 台账展示
台账列表 MUST 展示：账号、当前状态（无行显示「已开通（默认）」）、阻断原因、阻断时间、复核人/复核时间/复核说明，以及关联的逾期 EA 数量；支持按账号/状态筛选与分页。

#### Scenario: 无行账号展示
- **WHEN** 浏览台账且某账号从未被阻断
- **THEN** 该账号显示「已开通（默认）」，关联逾期数 0

#### Scenario: 筛选与分页
- **WHEN** 按状态 BLOCKED 筛选
- **THEN** 仅返回阻断中的账号
