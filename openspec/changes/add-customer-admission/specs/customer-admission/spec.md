# Spec Delta: customer-admission

## Purpose
客户主数据准入：集团视图与法人视图两级建档、CUST-NNNN 编码、税号与名称查重硬阻断、法人额度求和校验、启用/停用/冻结状态机与级联语义、客户合并编码锁定，全操作版本快照可回溯。

## ADDED Requirements

### Requirement: 集团视图建档与查重
系统 MUST 支持创建客户集团视图：客户编码由系统按 `CUST-` + 4 位流水自动生成且创建后不可修改，必填名称、税号、统一社会信用代码，可选集团信用评级与集团信用总额度。提交时系统 MUST 执行查重：税号精确匹配 + 名称编辑距离 ≤3 模糊匹配，命中时展示最近 3 条相似记录供确认（复用物料查重语义）；若税号已存在于**其它**集团视图，系统 MUST 以 L1 硬阻断拒绝建档并提示先走客户合并（BR-4.1-30）。名称相似但税号不同的，允许带差异说明继续创建。

#### Scenario: 税号重复硬阻断
- **WHEN** 新建集团视图提交的税号已存在于另一集团视图
- **THEN** 系统阻断建档，提示「税号已存在，须先走客户合并」，不生成新记录

#### Scenario: 名称相似提示
- **WHEN** 名称与既有客户编辑距离 ≤3 且税号不同，提交且未确认
- **THEN** 系统展示最近 3 条相似客户，确认并填写差异说明后方可创建

#### Scenario: 编码不可改
- **WHEN** 对已创建客户提交含新客户编码的变更
- **THEN** 系统阻断并提示编码创建后不可修改

### Requirement: 法人视图挂载与额度求和校验
系统 MUST 支持在集团视图下挂载多个法人视图（每法人一条）：必填法人主体、收货地址、联系人、联系电话、付款条件，可选本法人信用额度。保存时系统 MUST 校验 Σ 该集团下全部法人视图信用额度 × `GROUP_CREDIT_LIMIT_RATIO`（默认 100%）≤ 集团信用总额度，超限 MUST 阻断保存并提示调减或申请集团额度上调（BR-4.1-31）。集团信用总额度为空（未配置）时该校验 MUST 放行并给出提示。

#### Scenario: 额度超限阻断
- **WHEN** 保存法人视图后 Σ法人额度超过集团总额度
- **THEN** 系统阻断保存并提示超出金额与处置建议

#### Scenario: 同法人重复挂载
- **WHEN** 同一集团下对相同法人主体再次创建法人视图
- **THEN** 系统阻断并提示改用该法人既有视图

### Requirement: 客户状态机与冻结级联
客户集团视图 MUST 支持启用、停用、冻结三种状态转换：停用为软删除（新业务不可引用、历史可查、禁止硬删）；冻结 MUST 级联将其下全部法人视图标记为冻结（BR-4.1-34），解冻 MUST 级联恢复；已合并状态为终态，MUST 拒绝任何状态回退操作。下游销售订单对停用/冻结客户的引用阻断 MUST 以桩实现并明示模块未接入（BR-4.3-08 语义预留）。

#### Scenario: 集团冻结级联
- **WHEN** 将含 2 个法人视图的集团置为冻结
- **THEN** 集团与全部法人视图状态变为冻结，再次操作（解冻）同步恢复

#### Scenario: 停用阻断下游引用（桩）
- **WHEN** 停用一个客户且销售模块未接入
- **THEN** 影响分析返回空清单并携带「模块未接入」标记，页面明示口径，停用本身执行成功

#### Scenario: 已合并终态拒绝回退
- **WHEN** 对状态为已合并的客户提交启用/解冻操作
- **THEN** 系统拒绝并提示合并为终态、编码已锁定

### Requirement: 客户合并
系统 MUST 支持将源客户集团合并至目标客户集团：合并弹窗 MUST 提供税号/名称相似候选辅助选择；提交 MUST 校验源目标非同一客户、源客户未处于已合并状态、合并原因必填，并展示影响面（源客户下法人视图数量）。执行后 MUST：①源客户状态置为已合并且编码永久锁定（禁再启用/复用，C-4.1-10）；②源客户下全部法人视图改挂目标集团；③双方各生成 MERGE 版本快照（含原因与影响面）。合并为终态，系统 MUST NOT 提供自动回退（30 天回退为已知 Non-Goal）。

#### Scenario: 合并执行与改挂
- **WHEN** 源客户 A（含 2 个法人视图）合并至目标 B 并填写原因
- **THEN** A 状态变为已合并、A 的法人视图全部挂到 B 下、A 与 B 各生成一条 MERGE 快照

#### Scenario: 同法人冲突阻断
- **WHEN** 源客户与目标客户下存在相同法人主体的法人视图，发起合并
- **THEN** 系统阻断合并并列出冲突法人主体清单，提示先调整任一侧视图后再合并

#### Scenario: 影响面确认
- **WHEN** 打开合并弹窗选择源客户
- **THEN** 展示源客户下法人视图数量与原因必填项，未填原因时提交禁用

### Requirement: 版本快照与审计
建档、变更、状态转换、合并、法人视图增改 MUST 生成版本快照（记变更后新值，`OP_TYPE` 区分 CREATE/UPDATE/MERGE/DISABLE/FREEZE），支持任意两版本逐字段对比与版本历史查看。写操作 MUST 走乐观锁（verNo），冲突返回 409。

#### Scenario: 快照可回溯
- **WHEN** 修改集团信用评级并保存
- **THEN** 版本号递增，快照含变更后评级值与变更原因，详情页可与上一版本逐字段对比

### Requirement: 权限与事件桩
集团/法人视图的增删改、合并、状态操作 MUST 要求 ROLE_ADMIN（403），查询须已认证（401）。客户域写操作成功后 MUST 写入 `MDM.CUSTOMER.*` 事件日志桩（CREATED/UPDATED/CREDIT_UPDATED/MERGED），实现方式与既有物料事件桩一致。

#### Scenario: 非管理员建档
- **WHEN** ROLE_USER 提交创建集团视图
- **THEN** 返回 403，无数据写入
