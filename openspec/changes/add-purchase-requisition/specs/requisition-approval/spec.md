# Spec Delta: requisition-approval

## Purpose
请购审批（2.1.4）：以 Σ(数量×预估单价) 为判级金额的角色分级状态机审批（部门经理→采购总监→副总裁）、限额配置、通过/驳回重提、节点超时提醒与升级标记、审批日志留痕，落实 FR-4.2-1-2 与 BR-4.2-10。

## ADDED Requirements

### Requirement: 判级金额与分级路由
审批判级金额 MUST = Σ(各 PR 行 需求数量 × 预估单价)（询价前口径，需求已确认的行取确认后数量）。路由规则：金额 ≤ 部门审批限额 → 节点序列 [部门经理]；≤ 总监审批限额 → [部门经理, 采购总监]；> 总监审批限额 → [部门经理, 采购总监, 分管副总裁]。限额 MUST 来自配置项（`app.proc.dept-approval-limit` 默认 50000、`app.proc.director-approval-limit` 默认 500000），层级顺序 MUST 严格递进（部门 ≤ 总监）。提交审批时 MUST 生成对应节点的审批任务（初始节点激活），PR 头状态迁移「审批中」。

#### Scenario: 三级路由
- **WHEN** 判级金额 600000（> 500000）
- **THEN** 生成三个节点任务，首个激活节点为部门经理

#### Scenario: 单节点路由
- **WHEN** 判级金额 30000（≤ 50000）
- **THEN** 仅生成部门经理一个节点，通过即「已批准」

### Requirement: 通过与驳回重提
节点动作 MUST 支持：**通过**（存在后续节点 → 激活下一节点；否则 PR 状态迁移「已批准」并写 `PROC.PR.APPROVED` 事件）与 **驳回**（必填驳回原因 ≥2 字 → PR 状态回退「已驳回/待修改」，全部未完成节点任务作废并写 `PROC.PR.REJECTED` 事件）；被驳回的 PR MUST 可由申请人修改后**重新提交审批**（重新按当前判级金额路由，生成新任务序列，历史任务保留）。同一节点任务 MUST NOT 重复通过（二次提交 409/422 防重）。

#### Scenario: 逐级通过至批准
- **WHEN** 三级路由的三个节点依次通过
- **THEN** 每次通过激活下一节点，末节点通过后状态「已批准」且事件入 outbox

#### Scenario: 驳回退回
- **WHEN** 总监节点驳回并填原因
- **THEN** PR 状态「已驳回」，原因可查，申请人修改后可重新提交（生成新任务序列）

#### Scenario: 重复通过防重
- **WHEN** 同一节点任务被重复提交通过
- **THEN** 第二次请求被拒绝，无状态漂移

### Requirement: 超时提醒与升级标记（懒 sweep）
系统 MUST 懒扫描审批任务：节点停留超过 1 个工作日 MUST 打超时提醒标记；超过 3 个工作日 MUST 打升级标记（改派至上一级审批人，升级记录入审批日志）（BR-4.2-10 L3）；推送通知与自动改派为 TODO 桩，超时/升级标记与扫描时间 MUST 落库可查。仅未完成任务参与扫描。

#### Scenario: 超 1 日提醒
- **WHEN** 某审批任务停留 2 个工作日未处理
- **THEN** 任务打「超时提醒」标记，列表可见

#### Scenario: 超 3 日升级
- **WHEN** 任务停留 4 个工作日
- **THEN** 打「已升级」标记并记录升级对象（上一级），审批日志留痕

### Requirement: 审批视图与日志
审批页 MUST 按节点角色展示待办列表（当前项目角色简化：ADMIN 可执行全部节点动作，角色细分留后续——记入偏差），行内 MUST 展示判级金额、路由链路、物料历史 PR 预估价（审批辅助信息口径），以及操作按钮（通过/驳回）。每次审批动作 MUST 写入审批日志：任务、节点、动作、意见/原因、操作人、时间（L5 审计留痕），日志 MUST 可按 PR 查询展示。

#### Scenario: 审批日志完整
- **WHEN** 一张三级 PR 走完 通过→通过→通过
- **THEN** 审批日志 3 条记录，含节点、动作、操作人与时间

#### Scenario: 辅助信息展示
- **WHEN** 审批页打开某 PR
- **THEN** 展示判级金额、完整路由链、同物料历史 PR 预估价（无历史则明示暂无）

### Requirement: 权限与页面接入
审批动作（通过/驳回/提交审批/重新提交）MUST 要求 ROLE_ADMIN（403）；待办与日志查询须已认证（401）；页面挂载于菜单 2.1.4（`/m/2.1.4`，M2-1-4 已注册）；「待询价」状态的 PR MUST NOT 再出现在审批待办。

#### Scenario: 普通用户不可审批
- **WHEN** ROLE_USER 提交审批通过动作
- **THEN** 返回 403，任务状态不变

#### Scenario: 已批准不回待办
- **WHEN** PR 已批准后刷新待办列表
- **THEN** 该 PR 不再出现在待办
