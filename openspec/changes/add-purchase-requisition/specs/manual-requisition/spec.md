# Spec Delta: manual-requisition

## Purpose
手工请购（2.1.2）：业务部门非计划性需求的手工 PR 创建，需求来源与预算来源三选一约束、BR-4.2-09 待预算确认阻断、创建后直接进入审批，落实 FR-4.2-1-1 手工触发与 S-4.2-02。

## ADDED Requirements

### Requirement: 手工 PR 创建与字段约束
系统 MUST 支持手工创建 PR（单号规则与自动请购同：`PR-YYYYMMDD-NNN`）：行物料、需求数量、需求日期、预估单价、需求理由说明（≥2 字）必填；需求来源 MUST 三选一（项目编号 / 成本中心 / 内部订单号），选择成本中心时 MUST 从既有成本中心主数据下拉选择；预算来源 MUST 三选一（预算科目 / 成本中心 / 内部订单号）。物料状态校验与自动请购同口径：非 `STATUS='1'` MUST L1 硬阻断（BR-4.2-07）。手工 PR 初始状态 MUST 直接进入「待审批」或（预算来源缺失时）「待预算确认」，MUST NOT 经过确认步（S-4.2-02）。

#### Scenario: 必填与来源约束
- **WHEN** 提交缺少需求理由或需求来源均为空的 PR
- **THEN** 系统 422 逐项提示缺失字段

#### Scenario: 成本中心下拉
- **WHEN** 需求来源选择「成本中心」
- **THEN** 从既有成本中心主数据中选择，不存在的成本中心不可提交

### Requirement: 待预算确认阻断（BR-4.2-09）
预算来源三字段全空的提交 MUST 将 PR 状态置为「待预算确认」并 L1 阻断其流转询价（BR-4.2-09）；补录任一预算来源字段后 MUST 可提交进入「待审批」。已进入审批的 PR 若预算来源被清空 MUST 回落「待预算确认」。

#### Scenario: 无预算来源标记
- **WHEN** 提交预算来源三字段全空的手工 PR
- **THEN** PR 生成成功但状态为「待预算确认」，页面明示解禁条件，流转入口禁用

#### Scenario: 补录解禁
- **WHEN** 对「待预算确认」的 PR 补录预算科目后重新提交
- **THEN** 状态迁移「待审批」并生成审批任务

### Requirement: 手工 PR 编辑与权限
「待预算确认」「待审批被驳回」状态的手工 PR MUST 可编辑（含删除整单）；「审批中」及以上 MUST NOT 编辑（仅可等待审批或被驳回后编辑）；创建/编辑/删除 MUST 要求 ROLE_ADMIN（403），查询须已认证（401）；全部写操作 MUST 入操作日志（L5）。

#### Scenario: 审批中不可编辑
- **WHEN** 对状态「审批中」的手工 PR 提交编辑
- **THEN** 系统 422 阻断并提示须待审批结果或被驳回后再改

#### Scenario: 非管理员创建被拒
- **WHEN** ROLE_USER 调用手工 PR 创建接口
- **THEN** 返回 403，无数据写入
