# Spec Delta: mrp-auto-requisition

## Purpose
自动请购（2.1.1）：模拟 MRP 净算生成采购建议、按物料 Active 硬阻断生成 PR、MRP 来源 PR 的 80% 确认卡控与调减复核、催办升级标记、分批交付计划行、90 天懒关闭与 PO 反写桩，落实 FR-4.2-1-1 与 BR-4.2-07/08/50、C-4.2-11。

## ADDED Requirements

### Requirement: 模拟 MRP 净算与建议列表
系统 MUST 提供页内模拟 MRP 运算：录入或批量粘贴四类输入（需求量、现有库存、在制、在途）按 `NetReq = 需求量 − 现有库存 − 在制 − 在途`（FR-4.5-2-3）逐物料净算并返回建议列表。判定规则：`NetReq ≤ 0` MUST 标记「过量供给」且 MUST NOT 生成 PR；需求日期早于今天 MUST 标记「逾期/异常需求」（仍可生成，带异常标记并记录通知计划员的 TODO 桩）；输入数据 MUST NOT 落库（dry-run 语义，仅建议结果供勾选）。真实需求/供给源（4.5/WMS）未落地，输入为模拟值，接口 MUST 预留直读桩口径。

#### Scenario: 净算命中
- **WHEN** 某物料 需求 100、库存 30、在制 10、在途 20
- **THEN** 净需求 40，建议列表生成该物料建议量 40

#### Scenario: 过量供给不生成
- **WHEN** 需求 50、库存 80
- **THEN** NetReq = −30，标记「过量供给」，勾选与生成 PR 入口不可用

#### Scenario: 逾期需求标记
- **WHEN** 录入需求日期为昨天
- **THEN** 建议行标记「逾期/异常需求」，可生成 PR 且异常标记随行带入

### Requirement: PR 生成与物料状态硬阻断
勾选建议 MUST 生成请购单（单号 `PR-YYYYMMDD-NNN`，按日流水、唯一）；MRP 来源 PR 行 MUST 含：物料编码、需求数量、需求日期、预估单价、需求来源（枚举 工单/计划订单/销售订单/安全库存/模拟 + 来源单号文本，来源类型=MRP）、建议供应商（可空）。生成时 MUST 校验每行物料 `STATUS='1'`（已发布启用），非 Active（未发布/停用/归档）MUST L1 硬阻断并提示物料当前状态（BR-4.2-07）；生成的 PR 初始状态 MUST 为「待确认」并写入 `PROC.PR.CREATED` 事件（幂等键含 PR 单号与行标识，同版本重放 409）。

#### Scenario: 停用物料阻断
- **WHEN** 勾选的建议中含 STATUS='0' 的停用物料
- **THEN** 系统 L1 阻断整批生成并提示该物料当前状态

#### Scenario: 单号按日流水
- **WHEN** 同一天创建第 2 张 PR
- **THEN** 单号在 `PR-YYYYMMDD-` 前缀上递增序号

### Requirement: MRP PR 确认与 80% 卡控
待确认的 MRP PR 行 MUST 支持确认：确认时可调整需求数量与需求日期，但确认量 MUST ≥ 该行 MRP 建议量 × 80%（BR-4.2-08）；低于 80% 的确认 MUST 被阻断，除非填写调减理由并完成计划员复核标记（L2 降级：记录复核确认，复核留痕入操作日志）。确认完成的状态 MUST 迁移为「已确认」并写 `PROC.PR.CONFIRMED` 事件。

#### Scenario: 低于 80% 阻断
- **WHEN** 建议量 100，确认填 79 且未附调减理由与复核
- **THEN** 系统阻断并提示须 ≥80（或走调减理由+复核路径）

#### Scenario: 调减复核放行
- **WHEN** 确认量 70、填调减理由并完成计划员复核标记
- **THEN** 确认成功，操作日志记录 调减理由/复核人/原建议量

#### Scenario: 确认调整需求日期
- **WHEN** 确认时把需求日期顺延一周（数量不变）
- **THEN** 保存成功并入确认留痕

### Requirement: 催办与升级标记（懒 sweep）
系统 MUST 在查询/打开页面时懒扫描：生成超过 1 个工作日仍为「待确认」的 PR MUST 打催办标记；超过 3 个工作日 MUST 打升级标记（升级至采购经理）并留痕（BR-4.2-50 L3）；推送通知为 TODO 桩，标记与扫描时间 MUST 落库可查。

#### Scenario: 超 1 日催办
- **WHEN** 某 PR 生成于 2 个工作日前且仍待确认
- **THEN** 列表该行显示「已催办」标记与扫描时间

### Requirement: 分批交付计划行
PR 行 MUST 支持拆分多个交付计划行（交付日期 + 数量），Σ 交付数量 MUST ≤ 行需求数量（超出 422）；交付行的增改删 MUST 留痕（操作日志含前后值）。已关闭行 MUST NOT 再维护交付行。

#### Scenario: 超需求数量阻断
- **WHEN** 行需求 100，已有交付行合计 80，新增交付行 30
- **THEN** 系统 422 阻断（合计 110 > 100）

### Requirement: 关闭语义与 PO 反写桩
PR 行 MUST 支持手工关闭（必填关闭原因，已确认及之后状态）；C-4.2-11 懒 sweep MUST 自动关闭「需求日期 + 90 天仍未下达」的行并留痕（自动关闭原因系统生成）；系统 MUST 提供 PO 下达回写接口桩 `receivePoAllocation`（接收 PR 行与下达数量：累计下达 ≥ 需求数量 → 行自动关闭；超出 → 按 BR-4.2-51 返回阻断提示，例外路径待 2.3 收货调整单落地），当前无调用方，接口 400 级校验与状态迁移 MUST 可独立验证。

#### Scenario: 手工关闭必填原因
- **WHEN** 关闭一行未填原因
- **THEN** 系统 422 提示关闭原因必填

#### Scenario: 90 天自动关闭
- **WHEN** 某行需求日期已过 90 天且下达量为 0
- **THEN** 懒 sweep 将其关闭并记录自动关闭原因与时间

#### Scenario: PO 回写达量关闭
- **WHEN** 调用回写接口使累计下达量恰等于需求数量
- **THEN** 行状态迁移为已关闭；再次回写超出 → 返回 BR-4.2-51 阻断信息

### Requirement: 补充供应商与流转待询价
MRP PR 的完整路径 MUST 经审批（确认后由审批页提交审批 → APPROVING → APPROVED，FR-4.2-1-2 泛化口径，design D7）；**已批准（APPROVED）** 的 PR MUST 支持补充/修改建议供应商（供应商主数据下拉，可空保存）；存在至少一行已补供应商（非空）时 MUST 提供「流转询价」动作将 PR 头状态迁移为「待询价」（PENDING_RFQ）并写 `PROC.PR.*` 流转事件；未批准的 PR MUST NOT 出现流转入口；2.2 询价未落地，「待询价」为本变更终点状态。

#### Scenario: 无供应商不可流转
- **WHEN** 已批准但全部行的建议供应商均为空时点击流转
- **THEN** 系统阻断并提示至少一行须补充建议供应商

#### Scenario: 流转成功
- **WHEN** 已批准且一行供应商非空，点击流转
- **THEN** PR 头状态变为「待询价」，事件入 outbox

#### Scenario: 未批准无流转入口
- **WHEN** PR 仍处「已确认」（未提交审批或审批未完）
- **THEN** 页面不渲染流转按钮，接口 422 阻断
