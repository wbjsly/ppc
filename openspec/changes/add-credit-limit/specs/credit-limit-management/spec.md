# Spec Delta: credit-limit-management

## Purpose
客户信用额度全生命周期管理：法人常规与临时额度调整、临时额度到期自动回滚、集团基准（总额度/评级）调整、集团占用率超阈提示、基于版本快照的额度时间轴回溯、年度复审台账与超期自动压缩恢复。

## ADDED Requirements

### Requirement: 法人额度调整
系统 MUST 支持调整法人视图的常规信用额度与临时信用额度：常规额度保存时 MUST 复用求和校验（Σ本集团法人常规额度 ≤ 集团总额度 × `GROUP_CREDIT_LIMIT_RATIO`，超限 422 并提示调减或上调集团额度）；临时额度 MUST 伴填有效期且有效期必须晚于当天，否则阻断。全部调整 MUST 原因必填（≥2 字）、立即生效、生成含额度前后值的版本快照，并写入 `MDM.CUSTOMER.CREDIT_UPDATED` 事件日志桩。已合并客户的法人视图 MUST 拒绝调整（终态语义）。

#### Scenario: 常规额度超限阻断
- **WHEN** 调整后 Σ法人常规额度超过集团总额度
- **THEN** 系统阻断保存并提示超出金额与处置建议（调减或申请集团上调）

#### Scenario: 临时额度有效期校验
- **WHEN** 设置临时额度但有效期留空或早于/等于当天
- **THEN** 系统阻断保存并提示有效期必填且须晚于当天

#### Scenario: 调整入快照与事件桩
- **WHEN** 法人额度调整成功
- **THEN** 版本号递增，快照 diff 含旧值→新值与原因，日志出现 `MDM.CUSTOMER.CREDIT_UPDATED`

### Requirement: 临时额度到期回滚
处于有效期内的临时额度 MUST 计入可用信用额度试算；有效期截止日到达后，系统 MUST 将临时额度自动清零回滚并生成回滚快照（BR-4.1-33）。回滚 MUST 由双机制保障：定时任务周期扫描到期记录 + 客户数据被查询/调整时的懒校验兜底；两机制幂等（已回滚不重复处理）。

#### Scenario: 定时回滚
- **WHEN** 定时任务扫描到有效期 ≤ 当前日期的临时额度
- **THEN** 临时额度清零、生成 OP_TYPE 回滚语义的快照（含原临时值），日志记录回滚

#### Scenario: 懒校验兜底
- **WHEN** 定时任务尚未执行而用户打开信用额度页查看该客户
- **THEN** 页面展示的临时额度已按到期口径回滚（或展示回滚后值），不出现已过期仍计入的情况

### Requirement: 集团基准调整与占用率提示
系统 MUST 支持调整集团信用总额度与信用评级（求和基准），原因必填入版本快照；调整总额度后 MUST 重算占用率。列表或详情 MUST 展示集团额度占用率（Σ法人常规额度 ÷ 集团总额度），占用率 > 80% 时 MUST 以显著标记提示集团主数据管理员关注（BR-4.1-32，L4 提示不阻断）；集团总额度未配置时 MUST 展示「未配置」并跳过占用率计算而非显示错误值。

#### Scenario: 占用率超阈提示
- **WHEN** Σ法人常规额度 ÷ 集团总额度 = 85%
- **THEN** 该客户行展示 85% 与超阈黄标提示，调整动作不受阻

#### Scenario: 总额度未配置
- **WHEN** 集团信用总额度为空
- **THEN** 占用率展示「未配置」，不进行除零计算

### Requirement: 额度时间轴回溯
客户详情 MUST 提供额度时间轴：按版本快照列出全部额度相关变更（常规/临时/总额度/评级），每条含变更前后值、原因、操作人、时间，支持任意两版本逐字段对比（复用版本快照能力，不建独立调整单表）。

#### Scenario: 时间轴展示
- **WHEN** 客户经历多次额度调整后打开时间轴
- **THEN** 按版本升序展示每次调整的旧值→新值与原因，可选两版本对比

### Requirement: 年度复审台账
法人视图 MUST 记录年度复审日期（`LAST_REVIEW_DATE`）。距上次复审超过 12 个月时，系统 MUST 标记「复审超期」红标并按 `GROUP_CREDIT_LIMIT_RATIO` 自动临时压缩可用额度（L3 系统自动，写入快照留痕）；管理员执行「复审通过」MUST 更新复审日期为当天并恢复被压缩的额度（清除复审压缩标记）。未做过复审（日期为空）的新客户 MUST 视为未超期（宽限期口径，从建档日起算）。压缩与恢复 MUST 幂等。

#### Scenario: 超期自动压缩
- **WHEN** 某法人视图距上次复审超过 12 个月
- **THEN** 展示复审超期红标，可用额度被按 ratio 压缩并生成快照

#### Scenario: 复审通过恢复
- **WHEN** 管理员点击「复审通过」
- **THEN** 复审日期更新为当天，压缩解除、额度恢复原值，生成快照

#### Scenario: 新客户宽限
- **WHEN** 客户建档不足 12 个月且从未复审
- **THEN** 不标记超期、不压缩

### Requirement: 可用额度试算口径明示
系统 MUST 在页面展示可用信用额度计算公式：`可用 = 信用额度（含有效期内临时额度） - 应收账款余额 - 未清SO预占用 - 本次订单金额`（FR-4.3-2-2）。应收与未清 SO 涉及的字段当前为桩，MUST 明示「销售/财务域模块未接入，暂不计入」而非展示误导性数值；试算结果 MUST 随临时额度/压缩状态实时变化。

#### Scenario: 桩口径明示
- **WHEN** 打开可用额度试算区域且下游模块未接入
- **THEN** 公式完整展示，应收/未清 SO 项标注「未接入不计入」，试算值 = 当前有效信用额度

### Requirement: 权限与事件桩
额度调整、集团基准调整、复审操作 MUST 要求 ROLE_ADMIN（403）；查询与时间轴须已认证（401）。全部额度类写操作成功后 MUST 写入 `MDM.CUSTOMER.CREDIT_UPDATED`（或回滚/复审对应语义）日志桩，实现方式与既有事件桩一致。

#### Scenario: 非管理员调整
- **WHEN** ROLE_USER 提交额度调整
- **THEN** 返回 403，数据不变
