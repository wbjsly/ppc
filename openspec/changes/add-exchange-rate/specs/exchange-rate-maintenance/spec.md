# Spec Delta: exchange-rate-maintenance

## Purpose
汇率主数据维护：币种对/汇率类型/生效区间/来源文件编号模型，必填与 ISO 4217 格式校验，按币种对×汇率类型的区间不重叠不断档硬阻断，历史区间 append-only 不可篡改，按日期的汇率试算查询供财务域取数。

## ADDED Requirements

### Requirement: 汇率记录创建与必填校验
系统 MUST 支持创建汇率记录：基础币种与报价币种 MUST 为 3 位大写 ISO 4217 代码且二者不同；汇率类型 MUST 为 中间价/买入价/卖出价 三者之一；汇率值 MUST 大于 0 且按 6 位小数精度存储；生效日期、失效日期、来源文件编号 MUST 必填（BR-4.1-16 / C-4.1-04），失效日期 MUST 不早于生效日期。任一必填缺失或格式非法 MUST 以 L1 硬阻断拒绝保存。编码类字段无——记录标识由币对+类型+区间定位，创建生成版本快照（CREATE）并写入 `MDM.RATE.CREATED` outbox 事件（幂等键 `BASE/QUOTE:type:生效日期:vN`——含生效日以区分同序列多区间段，同记录重放仍被唯一索引拒绝）。

#### Scenario: 必填缺失阻断
- **WHEN** 提交缺少来源文件编号或生效日期的汇率记录
- **THEN** 系统 L1 阻断保存并逐项提示缺失字段

#### Scenario: ISO 4217 格式校验
- **WHEN** 基础币种提交为小写「usd」或四位「USDT」
- **THEN** 系统阻断并提示须为 3 位大写 ISO 4217 代码，且基础币种不得等于报价币种

#### Scenario: 汇率精度
- **WHEN** 提交汇率 7.1234567
- **THEN** 按 6 位小数精度存储为 7.123457（四舍五入），试算返回同精度

### Requirement: 区间冲突与断档阻断
区间校验 MUST 按（基础币种 × 报价币种 × 汇率类型）独立序列执行：新记录生效区间（闭区间 [生效日, 失效日]）与同序列既有任一区间相交 MUST 阻断并返回冲突区间清单（BR-4.1-17 / C-4.1-14）；存在断档（新记录生效日 > 同序列中最早的「上一条衔接区间」失效日 + 1 天时的区间链断点）MUST 阻断并提示衔接口径。同序列无任何既有记录时 MUST 放行（首条）。变更（编辑）记录时校验 MUST 排除自身区间。三类汇率类型（中间价/买入价/卖出价）在同一币对上 MUST 可各自独立维护互不干扰（对 BR-4.1-17「同一币种对」字面的解释性口径，偏差记录）。

#### Scenario: 区间相交阻断
- **WHEN** 同币对同类型已有 [2026-01-01, 2026-06-30]，新提交 [2026-06-01, 2026-12-31]
- **THEN** 系统阻断并返回冲突区间 [2026-01-01, 2026-06-30]

#### Scenario: 断档阻断
- **WHEN** 同序列上一条失效日为 2026-06-30，新提交生效日为 2026-07-02
- **THEN** 系统阻断并提示断档（新记录生效日须 ≤ 上一条失效日 + 1 天）

#### Scenario: 三类型独立
- **WHEN** 中间价已有 [2026-01-01, 2026-12-31]，新建同币对买入价区间完全重叠
- **THEN** 保存成功（不同汇率类型为独立序列）

### Requirement: 历史区间不可篡改
失效日期早于当天的记录（已失效历史）MUST 拒绝编辑与删除（422，BR-4.1-18「历史不被重算」的维护侧落地）；生效中与未生效记录 MUST 可变更（原因必填 ≥2 字入版本快照 UPDATE），变更后 MUST 重新执行区间冲突与断档校验。历史保留的另一面：试算按目标日期在区间内取数，后续新增记录 MUST NOT 影响已被历史区间覆盖日期的取数结果。

#### Scenario: 编辑历史被拒
- **WHEN** 对失效日期早于今天的记录提交变更
- **THEN** 系统 422 拒绝并提示历史区间不可篡改

#### Scenario: 生效中变更重跑校验
- **WHEN** 缩短生效中记录的失效日导致与后续记录断档
- **THEN** 系统阻断并返回断档提示，原记录不变

### Requirement: 汇率试算查询
系统 MUST 提供按（基础币种、报价币种、汇率类型、日期）的试算查询：返回目标日期落在生效区间内的记录（汇率值、区间、来源文件编号）；无命中 MUST 明示「该日期无有效汇率」并列出已排查原因（该币对无记录 / 区间不覆盖该日期 / 类型不匹配），MUST NOT 返回空对象让消费方猜测——为财务域凭证折算的「汇率缺失或过期提示」（FR-4.6-1-5）提供数据口径。汇率类型缺省时 MUST 按 中间价 优先、无中间价则依次尝试 买入价、卖出价，并在返回中标明实际使用的类型。

#### Scenario: 区间内命中
- **WHEN** 查询 USD/CNY 中间价 2026-10-03，存在 [2026-10-01, 2026-10-31] 区间
- **THEN** 返回该区间汇率值、来源编号与实际类型

#### Scenario: 缺失明示
- **WHEN** 查询日期不在任何区间内
- **THEN** 返回「该日期无有效汇率」与排查原因列表（非空结构）

### Requirement: 列表与生命周期展示
列表 MUST 支持按币种对、汇率类型、计算态筛选与分页；每条记录 MUST 按日期计算展示 未生效（生效日 > 今天）/ 生效中 / 已失效（失效日 < 今天）三种计算态标签（不落状态列）。已失效记录 MUST 不提供编辑与删除入口。

#### Scenario: 计算态标签
- **WHEN** 列表同时存在 未来生效、当前生效、已失效 三类记录
- **THEN** 各自展示对应计算态标签，筛选「生效中」仅返回当前区间覆盖今天的记录

### Requirement: 权限与事件
汇率记录的创建、变更 MUST 要求 ROLE_ADMIN（403）；列表、详情、试算查询须已认证（401）。全部写操作 MUST 生成版本快照（含前后值与原因），`MDM.RATE.CREATED/UPDATED` 事件写入 outbox（与客户/供应商事件共表，事件流页面可筛）。

#### Scenario: 非管理员录入
- **WHEN** ROLE_USER 提交创建汇率
- **THEN** 返回 403，无数据写入

#### Scenario: 事件可筛
- **WHEN** 汇率变更成功后在事件流按 `MDM.RATE.UPDATED` 筛选
- **THEN** 命中该事件，幂等键为 `币对:type:生效日期:vN` 格式（同序列不同区间段不撞键）
