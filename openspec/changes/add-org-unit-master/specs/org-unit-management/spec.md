# Spec Delta

## Purpose
组织单元主数据（3 级树形、六类类型、隶属法人主体），作为交易单据四要素（C-0-08）与行级权限过滤的权威数据源。

## ADDED Requirements

### Requirement: 组织单元树形列表查询
系统 SHALL 提供组织单元树形列表查询，支持按所属法人主体、类型、关键字（编码/名称）、状态筛选，返回结果按父子层级组织，节点携带层级号（1/2/3）与类型码。

#### Scenario: 按主体与类型筛选树
- **WHEN** 用户选择某法人主体与类型「仓库」提交查询
- **THEN** 系统仅返回该主体下类型为 WAREHOUSE 的节点及其祖先链，保持父子结构

#### Scenario: 关键字查询
- **WHEN** 用户输入关键字「OU-FACTORY」
- **THEN** 系统按编码或名称模糊匹配返回命中节点及其祖先链

### Requirement: 组织单元类型枚举
系统 SHALL 提供六类固定类型：工厂 FACTORY、仓库 WAREHOUSE、采购组织 PROC、销售组织 SALE、门店 STORE、研发中心 RD；新建与变更 MUST 从该六类中选择，非法类型值被拒绝。

#### Scenario: 新建选择类型
- **WHEN** 用户选择类型「工厂」新建组织单元
- **THEN** 节点类型为 FACTORY，编码按 `OU-FACTORY-{2位流水}` 生成

#### Scenario: 非法类型被拒绝
- **WHEN** 提交的类型不在六类枚举内
- **THEN** 系统以 L1 阻断拒绝并提示合法类型清单

### Requirement: 组织单元新建
系统 SHALL 支持新建组织单元，编码由系统按 `OU-{类型码}-{2位流水}` 自动生成（按类型独立计数、跨主体全局唯一、编码前缀与自身类型一致），保存后立即生效并生成版本 `V1` 快照；MUST 校验层级不超过 3 级；父节点与本节点 MUST 隶属同一法人主体；类型 MUST NOT 受层级限制（允许异构子节点）。

#### Scenario: 新建二级节点（异构类型）
- **WHEN** 用户在工厂 FACTORY 根节点下新建类型为 WAREHOUSE 的子节点
- **THEN** 系统生成编码 `OU-WAREHOUSE-01`，`TREE_LEVEL = 2`，保存成功并生成 V1 快照（类型不受父节点类型约束）

#### Scenario: 层级超过 3 级被阻断
- **WHEN** 用户尝试将新节点挂在第 3 级节点下
- **THEN** 系统以 L1 硬阻断拒绝并提示「组织单元层级最多 3 级」

#### Scenario: 跨主体父节点被阻断
- **WHEN** 用户为节点选择另一法人主体下的节点作为父级
- **THEN** 系统拒绝并提示父节点须与本节点隶属同一主体

### Requirement: 组织单元变更与版本快照
系统 SHALL 支持变更组织单元非编码字段（含变更父节点与类型）；每次变更立即生效，`verNo` 乐观锁防并发覆盖，变更后将整行新值写入版本表并生成递增版本号 N+1；编码字段变更 MUST 被阻断；变更类型时 MUST 校验现有编码前缀与新类型一致（不一致则阻断，编码不可改）；变更父节点 MUST 同时通过成环校验与深度校验。

#### Scenario: 变更父节点通过校验
- **WHEN** 用户将第 2 级节点改挂同主体另一第 1 级节点，改挂后深度不超 3 级
- **THEN** 系统保存新父级关系并重算 `TREE_LEVEL`，版本表新增 `V(N+1)` 快照

#### Scenario: 成环被阻断（DC-06）
- **WHEN** 用户尝试将某节点的父节点设置为其自身或其子孙
- **THEN** 系统以 L1 硬阻断拒绝并提示层级不得成环

#### Scenario: 变更类型与编码不一致被阻断
- **WHEN** 用户将编码为 `OU-FACTORY-01` 的节点类型改为 WAREHOUSE
- **THEN** 系统拒绝并提示编码创建后不可修改（类型与编码前缀绑定）

#### Scenario: 并发编辑冲突
- **WHEN** 后提交者 `verNo` 已不匹配
- **THEN** 系统阻断后提交者并提示刷新后重试

### Requirement: 组织单元停用与硬删禁止
系统 SHALL 支持将组织单元置为停用（软删除），停用后新业务不可引用但历史数据仍可查询；系统 MUST 禁止物理删除；当存在未停用子孙节点时停用 MUST 被阻断并列出这些子孙；当被下游业务数据引用时停用 MUST 被阻断并列出引用清单。

#### Scenario: 有未停用子孙时停用被阻断
- **WHEN** 用户停用一个仍有启用中子孙的节点
- **THEN** 系统阻断并列出全部未停用子孙的编码与名称

#### Scenario: 叶子节点正常停用
- **WHEN** 用户对无子孙、无下游引用的节点执行停用并确认
- **THEN** 状态变为 `Inactive`，记录仍可查询，版本表新增停用快照

#### Scenario: 物理删除请求被拒绝
- **WHEN** 任意客户端直接发起物理删除请求
- **THEN** 系统拒绝该请求，仅允许停用（C-4.1-03）

### Requirement: 组织单元详情与版本对比
系统 SHALL 提供组织单元详情抽屉与版本历史列表，并支持选择任意两个版本进行逐字段差异对比（含父节点、层级与类型字段）。

#### Scenario: 查看版本对比
- **WHEN** 用户选择 `V1` 与 `V3` 发起对比
- **THEN** 系统逐字段列出差异并高亮，展示操作人与变更时间

### Requirement: 组织单元数据供下游引用（C-0-08）
系统 SHALL 提供轻量组织单元选项接口（编码 + 名称 + 层级 + 类型），支持按法人主体过滤，仅返回启用中的节点，供交易单据四要素（C-0-08）、建号校验（行 8211）与行级权限（5.6）未来引用；当交易单据真实引用 `org_unit_id` 落地时 MUST 回补停用引用校验。

#### Scenario: 下游获取指定主体的启用选项
- **WHEN** 已登录客户端调用选项接口并传入法人主体 id
- **THEN** 系统返回该主体下全部启用节点的 `{id, code, name, level, type}` 列表

### Requirement: 访问权限控制
组织单元的增删改查接口 MUST 要求有效 JWT 认证；写操作（新建/变更/停用）MUST 限定 `ROLE_ADMIN`，非授权角色访问写接口时返回 403。

#### Scenario: 普通用户尝试变更
- **WHEN** 仅拥有 `ROLE_USER` 的登录用户调用变更接口
- **THEN** 系统返回 403 且不产生任何数据变更

#### Scenario: 未认证请求
- **WHEN** 未携带 JWT 的客户端调用树形列表接口
- **THEN** 系统返回 401 并跳转登录
