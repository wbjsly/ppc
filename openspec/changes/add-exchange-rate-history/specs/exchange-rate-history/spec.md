# Spec Delta: exchange-rate-history

## Purpose
汇率历史查询：按币对×汇率类型的区间历史链展示、跨记录全局版本快照时间线、任意两版本逐字段对比、历史值预填维护入口与时间线事件回显，落实 FR-4.1-3-4 历史保留、BR-4.1-18 审计留痕与 C-4.1-06 版本可回溯。

## ADDED Requirements

### Requirement: 区间历史链查询
系统 MUST 提供按（基础币种、报价币种、汇率类型）的区间历史链查询：返回该序列全部 append-only 区间记录（含已失效），按生效日期升序排列，每条 MUST 展示汇率值、生效/失效日期、来源文件编号、版本号与计算态标签（未生效/生效中/已失效，口径与 1.5.1 列表一致）。币对或类型缺失 MUST 以 422 拒绝；该序列无记录 MUST 返回空列表（前端明示「该序列暂无历史」），MUST NOT 报错。

#### Scenario: 全链含已失效
- **WHEN** 查询 USD/CNY 中间价，存在 2026 上半年已失效与 2026 下半年生效中两段
- **THEN** 返回两段完整区间，已失效段标注「已失效」计算态，按生效日期升序

#### Scenario: 序列为空
- **WHEN** 查询无任何记录的 EUR/CNY 买入价
- **THEN** 返回空列表而非错误

#### Scenario: 必填缺失
- **WHEN** 未提供报价币种
- **THEN** 返回 422 并提示币对必填

### Requirement: 全局版本快照时间线
系统 MUST 提供跨全部汇率记录的全局版本快照时间线（分页）：每条 MUST 含记录标识（币对/类型/生效区间）、版本号、操作类型（CREATE/UPDATE）、差异摘要、变更原因、操作人与创建时间，默认按创建时间倒序；MUST 支持按汇率类型、操作类型与关键字（币对或来源文件编号）筛选。时间线 MUST 覆盖所有已生成的版本快照（含批量导入逐行生成的快照），MUST NOT 因记录被软删或已失效而缺失其历史快照。

#### Scenario: 跨记录倒序分页
- **WHEN** 三条不同币对记录先后产生 4 个版本快照，请求 size=10
- **THEN** 按创建时间倒序一次返回全部 4 条，每条携带其所属记录标识

#### Scenario: 已删除记录的历史仍在
- **WHEN** 某记录被软删除（历史区间不可删故实际为管理员操作留痕），其此前的 CREATE/UPDATE 快照存在
- **THEN** 时间线仍返回这些快照，不因主记录 del_flag 过滤而缺失

#### Scenario: 关键字筛选
- **WHEN** 关键字输入 USD/CNY
- **THEN** 仅返回记录标识含该币对的版本快照

### Requirement: 两版本逐字段对比视图
系统 MUST 支持在同一记录的任意两个版本之间对比：前端选择 from/to 版本号后调用既有 diff 能力，返回变更字段清单（字段名、旧值、新值），MUST 逐字段并排展示并高亮（旧值红、新值绿）；字段值未变化的 MUST NOT 出现在差异清单。from/to 相同 MUST 前端禁用对比入口；版本号不存在 MUST 返回 404。

#### Scenario: 逐字段高亮
- **WHEN** 对比 V1→V2，仅 rate 与 expireDate 变化
- **THEN** 差异清单仅列这两行，V1 值红底、V2 值绿底

#### Scenario: 同版本禁用
- **WHEN** from 与 to 选择同一版本号
- **THEN** 前端禁用/不发起对比请求

### Requirement: 历史值预填维护入口（回滚降级）
时间线的 UPDATE 版本行 MUST 提供「按此历史值发起维护」入口：点击后跳转 1.5.1 汇率维护新建表单并预填该版本快照中的 基础币种、报价币种、汇率类型、汇率值、来源文件编号（生效/失效日期 MUST NOT 预填，由用户按当期口径重新指定）。历史页 MUST 为只读——MUST NOT 提供任何直接改写历史记录的回滚提交接口；预填后的保存 MUST 走 1.5.1 既有全量校验（必填、ISO 4217、BR-4.1-17 区间衔接、ADMIN 权限），校验不通过按既有 422 阻断（偏差记录：规格「一键回滚生成新版本」降级为预填再提交）。

#### Scenario: 预填跳转
- **WHEN** 点击某 UPDATE 版本行的预填入口
- **THEN** 打开 1.5.1 新建表单，币对、类型、汇率、来源文件编号已带入，生效/失效日期为空

#### Scenario: 预填保存仍受区间规则约束
- **WHEN** 预填的汇率区间与既有链冲突后提交
- **THEN** 按 BR-4.1-17 阻断并展示冲突信息，历史数据不发生任何变化

#### Scenario: 历史页只读
- **WHEN** 在历史页尝试任何写操作（页面无编辑/删除/回滚提交控件）
- **THEN** 无可用写入口，全部写能力保留在 1.5.1

### Requirement: 时间线事件回显
版本时间线 MUST 回显对应 `MDM.RATE.CREATED/UPDATED` outbox 事件：以该版本所属记录的（币对、类型、生效日期、版本号）重建幂等键匹配 `erp_ops_outbox`，展示事件类型、幂等键与投递状态；无匹配事件（历史遗留或消费方差异）MUST 显示「—」占位而非报错。匹配 MUST 为只读查询，MUST NOT 新发事件或改写 outbox 状态。

#### Scenario: 事件命中
- **WHEN** 某 CREATE 版本对应的 `MDM.RATE.CREATED` 事件已入 outbox
- **THEN** 该行展示事件类型、幂等键（`币对/type:生效日期:vN`）与投递状态

#### Scenario: 无事件占位
- **WHEN** 某版本快照无对应 outbox 记录
- **THEN** 事件列显示「—」，页面其余部分正常渲染

### Requirement: 权限与页面接入
历史页全部接口（区间链、时间线、事件回显）MUST 为只读且须已认证（401）；MUST NOT 需要写权限即可查看。页面 MUST 挂载于菜单 1.5.3（`/m/1.5.3`，M1-5-3 已注册）。1.5.1 维护页 MUST 支持从历史页跳转携带的预填参数打开新建表单，且不带参数进入时行为与现状一致。

#### Scenario: 未认证访问
- **WHEN** 未登录请求区间链或时间线接口
- **THEN** 返回 401

#### Scenario: 普通角色可查
- **WHEN** ROLE_USER 登录查看历史页
- **THEN** 可正常查询与对比（只读），但页面无任何写提交入口

#### Scenario: 无参进入维护页不受影响
- **WHEN** 直接访问 `/m/1.5.1`（无预填参数）
- **THEN** 表单为空打开，与历史页改造前行为一致
