# Spec Delta

## Purpose
替代关系的集中视图与维护（菜单 1.2.5）：补齐「替代物料编码已发布」参照 gap，含间接环防护与替代目标停用的引用完整性闭环。

## ADDED Requirements

### Requirement: 替代关系列表查询
系统 SHALL 提供替代关系列表：仅包含已配置替代（`altItemCode` 非空）的物料，展示源物料（编码/名称/状态）、目标替代物料（编码/名称/状态）；支持按「被替代物料（正向）」与「替代指向（反查谁引用了我）」两种维度及关键字、状态筛选，分页返回。

#### Scenario: 正向查看替代关系
- **WHEN** 用户打开替代物料页
- **THEN** 列出全部已配置替代的物料对（源 → 目标），目标状态一并展示

#### Scenario: 反查引用方
- **WHEN** 用户输入某物料编码作为「替代指向」筛选
- **THEN** 系统返回所有把该物料设为替代的源物料

### Requirement: 设置替代关系
系统 SHALL 支持为物料设置/清除替代关系，设置时 MUST 校验：目标物料**已发布（启用中）**（行 477）、目标**非自身**、目标的替代链上不出现本物料（**间接环阻断**，链路回溯深度上限 10）；设置成功立即生效并计入源物料版本快照（diff 记 `altItemCode` 变化）。

#### Scenario: 正常设置替代
- **WHEN** 用户为物料 A 设置启用中的物料 B 为替代
- **THEN** 保存成功，A 的 `altItemCode = B`，A 版本表新增快照且 diff 含 `altItemCode: （空） → B`

#### Scenario: 目标未发布被阻断
- **WHEN** 目标物料处于停用状态
- **THEN** 系统 L1 阻断并提示替代物料须已发布

#### Scenario: 自身替代被阻断
- **WHEN** 用户为物料 A 设置 A 自身为替代
- **THEN** 系统 L1 阻断

#### Scenario: 间接环被阻断并展示链路
- **WHEN** 已存在 B → C → A，用户为 A 设置 B 为替代
- **THEN** 系统 L1 阻断并展示环链「B → C → A」（回溯深度上限 10，超限按脏数据处理不放行）

#### Scenario: 清除替代
- **WHEN** 用户清除物料 A 的替代关系
- **THEN** `altItemCode` 置空，版本快照记录该变化

### Requirement: 物料表单替代参照校验
物料新建与变更提交时，若填写了替代物料编码，系统 MUST 执行与设置替代相同的三项校验（已发布、非自身、间接环），失败时高亮替代物料编码字段并返回原因。

#### Scenario: 表单填停用物料为替代
- **WHEN** 用户在物料新建表单的替代物料编码填入一个已停用物料的编码
- **THEN** 系统阻断提交并提示替代物料须已发布

### Requirement: 替代目标停用阻断
停用物料时，若该物料正被其他启用物料作为替代引用，系统 MUST 阻断停用并列出引用方（编码+名称，最多 10 条 + 总数），要求先调整引用方的替代指向。

#### Scenario: 被引用时停用被阻断
- **WHEN** 物料 B 被物料 A 指向为替代，用户停用 B
- **THEN** 系统阻断并列出引用方清单（含 A），B 保持启用

### Requirement: 停用时替代信息提示
物料停用确认界面 SHALL 展示该物料当前的替代指向；若未配置替代，SHALL 给出「建议指定替代」的非强制提示文案，不阻断停用流程。

#### Scenario: 未配置替代的停用提示
- **WHEN** 用户停用一个未配置替代的物料并确认
- **THEN** 确认框含「建议先指定替代物料」提示，确认后停用成功

### Requirement: 访问权限控制
替代关系维护（设置/清除）接口 MUST 要求有效 JWT 且限定 ROLE_ADMIN；列表查询认证即可；未授权 403、未认证 401。

#### Scenario: 普通用户尝试设置替代
- **WHEN** ROLE_USER 调用设置替代接口
- **THEN** 403 且关系无变化
