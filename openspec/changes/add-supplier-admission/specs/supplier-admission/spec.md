# Spec Delta: supplier-admission

## Purpose
供应商准入审核：SUP-NNNN 自动编码建档（四组字段+黑名单硬阻断+税号名称查重）、单步审核驱动的五态状态机、资质证照子表与到期治理（临期预警/到期受限/更新解除留痕）、影响分析桩口径与 Outbox 事件接入。

## ADDED Requirements

### Requirement: 供应商建档与查重
系统 MUST 支持创建供应商：编码由 `SUP-` + 4 位流水自动生成且创建后不可修改；基本信息（名称/地址/联系人/电话/法人主体）、财务信息（开户行/税号/付款条件）、合规信息（黑名单筛查结果/ESG 评估等级）必填项缺失 MUST 阻断。合规前置：黑名单筛查结果为「命中」时 MUST 以 L1 硬阻断拒绝建档并提示。查重 MUST 复用既有语义：税号精确匹配 + 名称编辑距离 ≤3，命中展示最近 3 条相似记录，确认非重复（forceCreate+差异说明）方可创建（C-4.1-07）。建档成功状态 MUST 为待审核，生成 CREATE 快照与 `MDM.SUPPLIER.CREATED` outbox 事件。

#### Scenario: 编码自动生成且锁定
- **WHEN** 首家供应商创建成功后提交修改编码
- **THEN** 创建返回 `SUP-0001` 序列编码，变更提交被阻断提示编码不可改

#### Scenario: 黑名单命中硬阻断
- **WHEN** 建档时黑名单筛查结果选择「命中」
- **THEN** 系统 L1 阻断建档并提示合规前置不通过

#### Scenario: 名称相似确认放行
- **WHEN** 名称与既有供应商编辑距离 ≤3 且税号不同，未确认即提交
- **THEN** 返回最近 3 条相似供应商，确认并填差异说明后创建成功

### Requirement: 单步准入审核
供应商创建后 MUST 处于待审核状态，未经审核 MUST NOT 进入合格（不可被下游新业务引用，options 仅含合格项）。审核通过（原因必填 ≥2 字）MUST 置为合格并生成 REVIEW 快照与 `MDM.SUPPLIER.REVIEWED` 事件；驳回（原因必填）MUST 留痕驳回原因并保持待审核（再次可提交审核）。审核动作 MUST 拒绝非待审核状态（422）。不建立双人复核审批流（基线降级）。

#### Scenario: 审核通过进入合格
- **WHEN** 对待审核供应商提交审核通过并填写原因
- **THEN** 状态变为合格，REVIEW 快照含原因，options 下拉出现该供应商

#### Scenario: 驳回保持待审核
- **WHEN** 对待审核供应商提交驳回并填写原因
- **THEN** 状态仍为待审核，快照记录驳回原因，可再次审核

#### Scenario: 非待审核态拒绝审核
- **WHEN** 对已合格供应商再次提交审核通过
- **THEN** 系统 422 拒绝

### Requirement: 五态状态机
供应商状态 MUST 为 待审核/合格/冻结/停用/证照过期 五态且迁移合法：合格 ⇄ 冻结、合格 ⇄ 停用、证照过期由到期自动置入、合格由证照更新核验自动恢复；待审核仅可被审核动作变更；停用为软删（新业务不可引用、历史可查、禁止硬删）；全部状态迁移 MUST 原因必填、乐观锁、生成对应快照与 `MDM.SUPPLIER.*` 事件。下游 PO 创建/过账对非合格状态的阻断 MUST 以桩实现并明示采购域未接入（BR-4.2-18 语义预留）。

#### Scenario: 合格冻结与解冻
- **WHEN** 对合格供应商执行冻结后执行解冻
- **THEN** 状态依次 合格→冻结→合格，各生成快照与事件

#### Scenario: 待审核不可直接停用
- **WHEN** 对待审核供应商提交停用
- **THEN** 系统 422 拒绝（须先审核或驳回后处理）

#### Scenario: 下游阻断桩明示
- **WHEN** 查看非合格供应商的影响分析且采购域未接入
- **THEN** 返回空清单并标注「采购域模块未接入，暂不计入」，停用/冻结本身可执行

### Requirement: 资质证照子表与到期治理
系统 MUST 支持供应商资质证照子表（可多条）：证照类型（营业执照/行业认证/其它）、证照编号、发证日期、有效期；增改 MUST 入供应商版本快照。列表查询时系统 MUST 前置懒巡检：供应商持有证照但**无任何有效证照**（全部有效期 ≤ 当天）且非证照过期态 → 自动置为证照过期受限态并入快照（幂等，行 805「到期当日置受限」；仍持有效证照者即使另有过期证照也不受限——与核验解除前置自洽，防解除被打回）；任一有效证照距当天 ≤ `CERT_EXPIRY_ALERT_DAYS`（默认 30 天）→ 临期黄标提示。证照更新（有效期 > 当天）且经核验动作 → 解除受限恢复合格并留痕（`MDM.SUPPLIER.CERT_RENEWED` 事件）。全部证照有效期均 > 当天的供应商 MUST NOT 被懒巡检置受限。

#### Scenario: 到期自动受限
- **WHEN** 供应商仅有的一条证照有效期为昨天且状态为合格，用户打开供应商列表
- **THEN** 该供应商状态被置为证照过期（受限），生成快照与 CERT_EXPIRED 事件

#### Scenario: 临期黄标
- **WHEN** 某证照有效期距今 20 天（≤30 天参数）
- **THEN** 列表/详情展示临期黄标提示，状态不变更

#### Scenario: 更新证照解除受限
- **WHEN** 证照过期供应商新增一条有效期为未来的证照并执行核验解除
- **THEN** 状态恢复合格，快照记录解除动作与原因，生成 CERT_RENEWED 事件

### Requirement: 影响分析与事件接入
供应商详情 MUST 提供影响分析：最早到期证照、是否受限、下游 PO 引用（桩明示采购域未接入，C-4.1-13 交期比对留采购域）。全部写操作（建档/变更/审核/状态/证照增改/解除）MUST 在同一事务内写入 `erp_ops_outbox` 事件（`MDM.SUPPLIER.*` 类型，幂等键 `编码:vN` 或 `编码@证照:vN`），与客户域共用事件表，事件流页面可按供应商事件类型筛选。

#### Scenario: 写操作产生 outbox 事件
- **WHEN** 供应商审核通过成功
- **THEN** outbox 新增 `MDM.SUPPLIER.REVIEWED` 事件，幂等键含供应商编码与版本，STATUS=PENDING

#### Scenario: 影响分析桩口径
- **WHEN** 打开合格供应商的影响分析且采购域未接入
- **THEN** 展示最早到期证照与临期状态，PO 引用区标注「采购域模块未接入」不展示虚假数值

### Requirement: 权限与审计
建档、变更、审核、状态操作、证照增改与核验 MUST 要求 ROLE_ADMIN（403）；列表、详情、影响分析、合格 options 须已认证（401）。全部写操作 MUST 生成含前后值与原因的版本快照（可任意两版本对比）。

#### Scenario: 非管理员审核
- **WHEN** ROLE_USER 提交审核通过
- **THEN** 返回 403，状态不变

#### Scenario: 版本可回溯
- **WHEN** 供应商经历建档→审核→冻结后查看版本历史
- **THEN** 三条快照按版本升序展示，OP_TYPE 分别为 CREATE/REVIEW/FREEZE，含原因与差异摘要
