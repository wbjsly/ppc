# Spec Delta: rfq-comparison-award

## Purpose
比价与定标（2.2.1 后半）：比价矩阵（含税单价跨税码域试算、权重加权总分、±20% 异常处理、谈判双轨）、比价分析表登记、定标前置校验与 AWARDED 终点、中选结果查询桩，落实 FR-4.2-2-2、BR-4.2-12/13/14。

## ADDED Requirements

### Requirement: 比价矩阵与含税单价
RFQ 详情 MUST 提供比价矩阵：每家有效报价展示 **单价、含税单价、交货期、MOQ、付款条件、报价有效期**；含税单价 = 单价 ×（1 + 税率），税率 MUST 按 RFQ 创建日期调用税码试算（`erp_mdm_tax_code` 按日期覆盖区间取数）——该日期无税码覆盖时含税列 MUST 明示「待税率」而非留空或报错。矩阵 MUST 提供桩列（历史准时交付率/来料合格率/质量等级/供应商综合评分，显示「待接入」），供后续 PO/质检数据接入。

#### Scenario: 含税单价计算
- **WHEN** 税码 VAT-13 覆盖 RFQ 创建日，单价 100
- **THEN** 含税单价显示 113（100×1.13，4 位小数内）

#### Scenario: 无税率明示
- **WHEN** 该日期无任何税码覆盖
- **THEN** 含税列显示「待税率」，矩阵其余功能不受影响

### Requirement: 权重可调加权总分
矩阵 MUST 支持价格权重与交付权重（整数百分比，合计必须 = 100%，否则 422）并实时计算加权总分：价格分 = 本单价的相对最优分（最低有效单价 ÷ 本单价 × 100）、交付分 = 相对最优分（最短交期 ÷ 本交期 × 100，缺交期按 0 分，剔除/无效报价不参与且不计排名）；总分 = 价格分 × 价格权重% + 交付分 × 交付权重%，按总分降序展示。权重调整 MUST 前端即时重算（无需保存），权重值随定标留痕存入 RFQ。

#### Scenario: 权重合计校验
- **WHEN** 价格权重 60、交付权重 50（合计 110）
- **THEN** 422 提示合计须为 100%

#### Scenario: 低价高分排序
- **WHEN** 三家报价 100/110/120、交期相同
- **THEN** 总分排序 100 者第一（100/90.9/83.3）

### Requirement: 异常偏离确认与剔除（BR-4.2-12）
矩阵 MUST 自动计算有效报价均值并标记：`|单价 − 均值| ÷ 均值 > 20%` 的报价标「异常偏离」（L4）；异常报价 MUST 可由采购员逐条 **确认保留**（记确认人/时间）或 **剔除**（报价置无效，不参与均值、加权与定标，剔除须填原因）；存在未处理（未确认且未剔除）的异常报价时定标 MUST 422 阻断。剔除后均值与总分 MUST 重新计算。

#### Scenario: 异常标记
- **WHEN** 有效报价 100/100/160
- **THEN** 160 被标异常偏离（偏离 42.9% > 20%）

#### Scenario: 未处理阻断定标
- **WHEN** 存在异常报价既未确认也未剔除
- **THEN** 定标 422 提示须先处理异常偏离报价

#### Scenario: 剔除重算
- **WHEN** 剔除 160 的报价后
- **THEN** 均值回到 100，被剔除报价显示无效不参与排名

### Requirement: 谈判双轨留存（BR-4.2-14）
定标前 MUST 支持对报价录入谈判后单价与谈判说明：**原始报价 MUST 保留不覆盖**，矩阵双列（原始/谈判后）展示，加权总分与均值判定 MUST 以谈判后单价（如有）参与计算并标注「谈判后」；谈判记录（原单价→谈判后单价、说明、操作人、时间）MUST 留痕可查（L5）。

#### Scenario: 双轨并存
- **WHEN** 单价 100 谈判至 95
- **THEN** 矩阵同列显示 100（原始）与 95（谈判后），加权按 95 计算

### Requirement: 定标与中选桩
定标 MUST 校验：状态 = `QUOTED_CLOSED`（已锁价）、中选供应商存在有效（未剔除）报价、异常报价已全部确认/剔除、有效报价数 ≥ `MIN_QUOTE_COUNT` 或有效紧急放行、比价分析表编号（≥4 字符）与结论（≥2 字）必填、权重合计 100——全部通过 → 状态 `AWARDED`、记录中选供应商/成交单价（取谈判后单价否则原始）/分析表字段/权重快照，写 `PROC.RFQ.AWARDED` 事件（diff 含中选供应商与成交价）。系统 MUST 提供 `GET /api/proc/rfqs/awarded?prNo=` 查询桩：返回该 PR 的中选 RFQ（单号、中选供应商、成交单价、紧急标识），无 → 明示「无中选结果」结构；供 2.3.1 订单创建消费。定标动作 MUST NOT 生成 PO（范围边界）。

#### Scenario: 定标成功
- **WHEN** 锁价后 3 家有效报价、异常已处理、分析表齐全、选中一家
- **THEN** 状态 AWARDED，事件入 outbox，成交单价取谈判后值（如有）

#### Scenario: 不足阻断
- **WHEN** 有效报价 2 家 <3 且无紧急放行
- **THEN** 定标 422（INSUFFICIENT 路径）

#### Scenario: 中选桩查询
- **WHEN** 按已定标 PR 查询 awarded
- **THEN** 返回 RFQ 单号与中选供应商结构；未定标 PR 返回 emergency:false 同款明示结构
