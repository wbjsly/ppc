# Proposal

## Why

物料管理二级菜单下 1.2.1 新建 / 1.2.2 变更 / 1.2.4 停用 / 1.2.5 替代四个三级菜单，本质是**同一个物料列表的四种动作视角**（新建与变更本就共用 `item/index.vue`，仅 `meta.mode` 不同；停用工作台与替代页是该列表的筛选增强）。四个入口割裂了「一个物料全生命周期在一处操作」的心智模型，用户需在菜单间跳转完成同一对象的连续动作。整合为单一列表页，减少入口冗余、统一操作动线。

## What Changes

- **菜单整合（方案 C 全合一）**：1.2.1/1.2.2/1.2.4/1.2.5 四菜单合并为一个「**物料管理**」（1.2.1，`/m/1.2.1`）；1.2.3 分类维护改号为 **1.2.2**（`/m/1.2.2`）
- **单列表页重构**（`views/mdm/item/` 内部装配，不揉成巨石）：工具栏 = 新建 + 批量停用 + 关键字/状态（启用/停用/已归档）/有无替代/维度（正向/反查）筛选；列表列 = 编码/名称/分类/状态/替代指向（失效红标）/操作；行操作 = 变更、停用/启用/归档、替代（设置/清除）、影响分析
- **动作下沉为子组件**：原三页面复用装配 —— 表单（新建/变更，含 477 替代校验与查重）、替代弹窗、影响分析抽屉、停用/启用/归档确认（原因必填）拆为 `item/` 目录子组件；主页面仅保留列表 + 工具栏 + 弹窗编排
- **保留双停用入口**：工具栏批量停用 + 行内单条停用（共用后端端点）
- **替代正反查降级为筛选器**：原 1.2.5 页的方向 radio 与失效红标并入工具栏/列表列
- **删除**：`views/mdm/item-disable/`、`views/mdm/substitute/` 目录；`meta.mode='change'` 与 `isChangeMode` 逻辑；路由 `/m/1.2.4`、`/m/1.2.5` 改重定向，`/m/1.2.2` 改指向分类维护（见 Impact 路由兼容）
- **菜单/文档同步**：改 `docs/design/08-erp-menu.md` 菜单树 → 重生成 `099-menu-seed.sql`（`generate-menu-seed.cjs`，勿手工编辑）；**新增迁移 `100-menu-consolidate.sql`** 修正存量库菜单行（099 已执行 marker 已记录，`INSERT IGNORE` 不更新旧行）
- **后端**：仅 `GET /api/mdm/items` 分页加 `hasSubstitute` 筛选参数（1 有替代 / 0 无替代；spec「是否配置替代」筛选的最小落点）；其余端点（impact/enable/archive/batch/substitutes/477 校验）全部复用

| 条目 | 处理 |

## Impact

- **前端**：`views/mdm/item/index.vue` 重构装配 + 新增子组件（表单/替代弹窗/影响抽屉/停用确认）；`api/mdm/item-disable.js`、`api/mdm/substitute.js` 保留复用；删除 `views/mdm/item-disable/`、`views/mdm/substitute/`；`router/index.js` 路由收缩与重定向
- **菜单**：`docs/design/08-erp-menu.md` → `node backend/scripts/generate-menu-seed.cjs` 重生成 099 → 新迁移 `db/mysql/100-menu-consolidate.sql`（更新/删除存量 `erp_admin_menu` 行，幂等）
- **数据**：仅 `erp_admin_menu` 行调整；物料/版本表不动
- **回归面**：物料新建、变更、停用工作台、替代关系、分类维护五个既有流程全部要在新入口复验；菜单管理页与 `M1-2` 子树展示同步
- **风险**：菜单编号变动影响外部对 `/m/1.2.x` 的书签与 08 文档下游引用（497 三级菜单中 1.2.x 是唯一被整合的子树，其余不动）
