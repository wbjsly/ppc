# Proposal

## Why

1.6.2 政策台账已在 `add-tax-code` 交付，但存在两处与规格/基线的落差：① 政策编辑的变更记录仅落操作日志，无版本快照、无变更事件（与「主数据版本控制：所有主数据变更自动生成版本快照」及税码/汇率域基线不一致，原提案偏差表已记「仅日志」需回填）；② S-4.1-07「因政策调整批量更新税码、新旧税率在切换日期无缝衔接」的**执行侧**未闭环——台账只能"看"关联变更，不能"发起"政策驱动的批量切换。本变更一次补齐两块。

## What Changes

### 能力一：政策版本快照 + 变更事件 + 页内对比

- **迁移 027**：`erp_mdm_tax_policy_version` 快照表（与税码/汇率版本表同构：ENTITY_ID+VERSION_NO 唯一、SNAPSHOT_JSON、DIFF_SUMMARY、OP_TYPE、CHANGE_REASON）
- 政策登记/编辑 生成 CREATE/UPDATE 快照（diff = 七字段前后值对比；政策无必填原因字段，CHANGE_REASON 置空）；outbox `MDM.POLICY.CREATED/UPDATED`，幂等键 `政策文号:{政策ID前8位}:vN`（N=快照版本号，同记录同版本重放 409，沿 add-tax-code D3 口径）
- **版本对比抽屉**：政策行「对比」→ from/to 版本下拉 → 逐字段红绿高亮（复用税码页样式）；新增 `GET /tax-policies/{id}/versions` 与 `GET /tax-policies/{id}/diff`
- 存量政策无历史快照：**不回填**，首个快照由本变更后的首次写操作生成（design 记口径）

### 能力二：政策驱动批量变更工作台（S-4.1-07 闭环）

- **入口**：1.6.2 政策行「发起变更」→ 全屏抽屉四步：勾选税码 → 参数 → 预检 → 提交报告
- **候选查询** `GET /tax-policies/{id}/candidates`：非软删税码（带计算态、链尾失效日、建议新段生效日=链尾+1），支持税码编号/关键字筛选
- **参数**：**统一切换生效日 + 统一新段失效日（顶部默认值），每行可单独覆盖**；行内新段的适用范围/计税方式/税率类型 **继承原记录不可改**（工作台只调税率与政策归属）
- **预检（dry-run）**：逐行生成执行计划并校验（不落库），计划类型：
  1. 空链 → 新建首段
  2. 切换日 = 链尾+1 → 直接新建衔接段
  3. 切换日落在**未失效尾段**内部 → 缩短尾段至切换日-1 + 新建段（历史已失效区间不动）
  4. 切换日落在**中间未失效段**（其后已有后续段）→ 缩短该段 + 新建段且新段失效日**自动=后续段生效日-1**（保证无缝贴合）
  5. 其他（切换日早于今天 / 落入已失效历史 / 早于链首 / 空洞断档）→ 422 可操作口径
- **提交**：**行级独立事务**——缩短走 `MdmTaxCodeService.update`（原因自动生成：`政策切换缩短，依据 {政策文号}`），新建走 `MdmTaxCodeService.create`（快照+`MDM.TAXCODE.CREATED` 逐行生成，**新段政策文号自动=所选政策**）；单行失败收集不回滚成功行，出结果报告（含缩短/新建两类动作明细）
- **切换日 ≥ 今天（L1）**：防追溯改写历史核算口径（BR-4.1-18 的工作台侧落地）
- 权限：全部接口 ADMIN；页面挂 `/m/1.6.2`，不新增菜单

### 与规格的关系

| 规格条目 | 处理 |
|---|---|
| **S-4.1-07 政策驱动批量更新+切换日无缝衔接（L555/720）** | **补齐**（工作台预检/提交） |
| **BR-4.1-17 区间不重叠不断档** | **补齐**（计划生成与提交双重校验，复用 `IntervalRules`） |
| **BR-4.1-18 历史不被重算** | **补齐**（切换日≥今天；缩短仅作用于未失效段；已失效区间零改动） |
| 主数据版本控制（L458 所有变更生成快照） | **回填**（政策快照+事件，替代原「仅日志」口径） |
| C-4.1-04 政策文号必附 | **沿用**（新段自动带所选政策文号） |

### 偏差表

| 项 | 口径 | 级别 |
|---|---|---|
| 政策编辑变更原因 | 沿现状不强制原因（快照 CHANGE_REASON 置空），与税码/汇率「原因≥2字」不同——政策为低频台账，需求确认过基线未含此项 | 解释性口径 |
| 存量政策快照回填 | 不回填，首快照由本变更后首次写操作生成 | 范围裁剪 |
| 工作台新段字段 | 适用范围/计税方式/税率类型继承不可改（只调税率），避免工作台绕过单条维护的语义 | 设计口径 |

## Capabilities

### New Capabilities

- `tax-policy-workbench`: 政策版本快照与 MDM.POLICY 事件、政策页版本对比、受影响税码候选查询、政策驱动切换的预检计划（五类计划与阻断口径）、行级提交与结果报告、切换日≥今天与历史保护、权限口径

### Modified Capabilities

（无——`tax-policy-register` 的既有行为（登记/锁定/禁删/回链）不变，快照与事件为新增能力面，归入新 capability；主规格尚未归档，避免跨变更 delta 依赖）

## Impact

- 后端：迁移 `027-tax-policy-version.sql`；`MdmTaxPolicy`（无字段变化）+ 新 `MdmTaxPolicyVersion` 实体/DAO；`MdmTaxPolicyService` 补快照/事件/versions/diff；新 `MdmTaxWorkbenchService/Controller`（candidates/preview/submit，挂 `/api/mdm/tax-policies/{id}/workbench/*`）；复用 `MdmTaxCodeService.create/update`、`IntervalRules`、`OutboxPublisher`
- 前端：`tax-policy/index.vue` 行加「对比」「发起变更」+ 对比抽屉 + 工作台抽屉（四步）；`api/mdm/tax-policy.js` 扩展
- SecurityConfig：workbench 写路径已在 `tax-policies/**` ADMIN 规则覆盖（POST）——**核对通配是否含子路径**，不足则补
- 无 1.6.1/1.6.3 改动；无新菜单
