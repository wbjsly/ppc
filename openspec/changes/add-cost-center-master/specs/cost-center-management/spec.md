## ADDED Requirements

### Requirement: 成本中心树形列表查询
系统 SHALL 提供成本中心树形列表查询，支持按所属法人主体、关键字（编码/名称）、状态筛选，返回结果按父子层级组织，节点携带层级号（1/2/3）。

#### Scenario: 按法人主体筛选树
- **WHEN** 用户选择某法人主体并提交查询
- **THEN** 系统仅返回隶属该主体的成本中心及其子孙节点，保持父子层级结构

#### Scenario: 关键字查询
- **WHEN** 用户输入关键字「PROD」
- **THEN** 系统按编码或名称模糊匹配返回命中节点及其祖先链，保证树形上下文可见

### Requirement: 成本中心新建
系统 SHALL 支持新建成本中心，编码由系统按 `CC-{类型码}-{2位流水}` 自动生成（类型码取自成本类型：生产 PROD / 销售 SALES / 管理 ADMIN / 研发 RD，流水按类型独立计数），保存后立即生效并生成版本 `V1` 快照；MUST 校验层级不超过 3 级。

#### Scenario: 新建二级节点成功
- **WHEN** 用户选择成本类型「生产」、父节点为既有根节点 `CC-PROD-01`，填写名称后提交
- **THEN** 系统生成编码 `CC-PROD-02`，节点 `TREE_LEVEL = 2`，列表可见，版本表存在其 `V1` 快照

#### Scenario: 层级超过 3 级被阻断
- **WHEN** 用户尝试将新节点挂在第 3 级节点下
- **THEN** 系统以 L1 硬阻断拒绝保存并提示「成本中心层级最多 3 级」

#### Scenario: 必填项缺失被阻断
- **WHEN** 用户未选择所属法人主体或成本类型即提交
- **THEN** 系统拒绝保存并高亮定位缺失字段

### Requirement: 成本中心变更与版本快照
系统 SHALL 支持变更成本中心非编码字段（含变更父节点）；每次变更立即生效，`verNo` 乐观锁防并发覆盖，变更后将整行新值写入 `erp_mdm_cost_center_version` 并生成递增版本号 N+1；编码字段变更 MUST 被阻断；变更父节点时 MUST 同时通过成环校验与深度校验。

#### Scenario: 变更父节点通过校验
- **WHEN** 用户将第 2 级节点改挂到同主体另一第 1 级节点下，且改挂后深度不超过 3 级
- **THEN** 系统保存新父级关系，`TREE_LEVEL` 相应更新，版本表新增 `V(N+1)` 快照记录该状态

#### Scenario: 成环被阻断（DC-06）
- **WHEN** 用户尝试将某节点的父节点设置为其自身或其子孙节点
- **THEN** 系统以 L1 硬阻断拒绝提交并提示层级不得成环

#### Scenario: 并发编辑冲突
- **WHEN** 两名用户基于同一版本同时编辑，后提交者 `verNo` 已不匹配
- **THEN** 系统阻断后提交者并提示刷新后重试，库中保留先提交者数据

#### Scenario: 尝试修改编码
- **WHEN** 变更请求包含对成本中心编码的修改
- **THEN** 系统以 L1 硬阻断拒绝并提示编码创建后不可修改（C-4.1-01）

### Requirement: 默认成本中心标记
系统 SHALL 支持将某成本中心标记为所属法人主体的默认中心；同一法人主体下 MUST 至多一个默认中心，置默认时同主体其他节点自动取消默认。

#### Scenario: 置默认自动清除旧默认
- **WHEN** 用户将主体 A 下的 `CC-ADMIN-02` 设为默认，此前 `CC-ADMIN-01` 已是默认
- **THEN** 保存后 `CC-ADMIN-02` 为默认、`CC-ADMIN-01` 自动变为非默认，两者版本表各新增一条快照

### Requirement: 成本中心停用与硬删禁止
系统 SHALL 支持将成本中心置为停用（软删除），停用后新业务不可引用但历史数据仍可查询；系统 MUST 禁止物理删除；当节点仍有未停用子孙节点时停用 MUST 被阻断并列出这些子孙；当节点被下游业务数据引用时停用 MUST 被 L1 硬阻断并列出引用清单。

#### Scenario: 叶子节点正常停用
- **WHEN** 用户对无子孙、无下游引用的节点执行停用并确认
- **THEN** 状态变为 `Inactive`，记录仍可查询，版本表新增停用快照

#### Scenario: 有未停用子孙时停用被阻断
- **WHEN** 用户停用一个仍有启用中子孙的节点
- **THEN** 系统阻断停用并列出全部未停用子孙的编码与名称

#### Scenario: 物理删除请求被拒绝
- **WHEN** 任意客户端直接发起物理删除请求
- **THEN** 系统拒绝该请求，仅允许停用（C-4.1-03）

### Requirement: 成本中心详情与版本对比
系统 SHALL 提供成本中心详情抽屉与版本历史列表，并支持选择任意两个版本进行逐字段差异对比（含父节点与层级字段）。

#### Scenario: 查看版本对比
- **WHEN** 用户在版本历史中选择 `V1` 与 `V2` 发起对比
- **THEN** 系统逐字段列出差异（如 `parentId`、`treeLevel`、`costType`）并高亮，展示操作人与时间

### Requirement: 成本中心数据供下游引用
系统 SHALL 提供轻量成本中心选项接口（编码 + 名称 + 层级），支持按法人主体过滤，供后续凭证行、请购单、资产卡片、报销单等模块引用；仅返回启用中的节点。

#### Scenario: 下游获取指定主体的启用节点
- **WHEN** 已登录客户端调用选项接口并传入法人主体 id
- **THEN** 系统返回该主体下全部 `status = Active` 节点的 `{id, code, name, level}` 列表

### Requirement: 访问权限控制
成本中心的增删改查接口 MUST 要求有效 JWT 认证；写操作（新建/变更/停用/设默认）MUST 限定 `ROLE_ADMIN`，非授权角色访问写接口时返回 403。

#### Scenario: 普通用户尝试变更
- **WHEN** 仅拥有 `ROLE_USER` 的登录用户调用变更接口
- **THEN** 系统返回 403 且不产生任何数据变更

#### Scenario: 未认证请求
- **WHEN** 未携带 JWT 的客户端调用树形列表接口
- **THEN** 系统返回 401 并跳转登录
