## Context
首个**树形**主数据模块（法人主体是平铺的）。约束同前：JDK 17 + Spring Boot 2.7.18 + MyBatis-Plus，无工作流引擎；表名 `erp_mdm_` 前缀；迁移用 `DbBootstrap`。父级挂法人主体，复用 `legal-entities/options`。

## Goals / Non-Goals
- Goals：3 级树形 CRUD + 停用 + 版本快照 + 成环/深度校验；编码自动生成；默认中心标记
- Non-Goals：科目/利润中心映射、审批流、未来生效日期、主体合并、撤销余额真实校验（留桩）

## Decisions

**1. 树形存储：`PARENT_ID` 自引用 + 显式 `TREE_LEVEL`（1/2/3）**。
- `TREE_LEVEL` 冗余存储（而非查询时递归计算），使「深度 ≤ 3」成为一次条件判断，同时树形展示直接按 level 分组。
- 成环校验（DC-06）：变更父节点时从新父节点向上回溯至根，路径中出现自身 ID 即阻断；因深度上限 3，回溯成本 O(3)。
- 备选：物化路径 `PATH`（如 `/le-0001/cc-01/cc-02/`）→ 拒绝，路径维护（改父节点需重写子孙路径）比回溯复杂且收益小。

**2. 编码 `CC-{类型码}-{2位流水}`，按类型独立计数**：类型码由 `COST_TYPE` 固定映射（PROD/SALES/ADMIN/RD），流水取同类型最大码 +1，唯一索引 `UK_MDM_CC_CODE` 兜底并发重试（同法人主体的生成逻辑）。
- 编码生成范围不区分法人主体（跨主体全局唯一），避免多主体下编码撞车引发下游引用歧义。
- 变更成本类型**不重刷编码**（C-4.1-01 编码不可改的延伸），但校验「编码前缀与当前类型一致」——存量数据类型未改时恒一致，防御手工改库场景。

**3. `IS_DEFAULT` 每法人主体至多一个**：置默认时同主体其他中心自动置 0（服务层事务内执行），来源于 FR-4.6-5-4「默认成本中心」。仅叶子节点可设默认（3 级树中根/中间节点通常是归集容器，无凭证行直接挂载）——此为推断，风险见下。

**4. 停用策略：父节点停用阻断**，要求先停用全部子孙（列出清单），避免树断链与下游引用歧义。子节点可先于父节点停用（同级顺序无关）。

**5. 版本快照复用法人主体模式**：`erp_mdm_cost_center_version`，`SNAPSHOT_JSON` 存该版本状态（变更后新值），含 `TREE_LEVEL`、`PARENT_ID`，diff 逐字段计算。

## Risks / Trade-offs
- 「仅叶子可设默认」是推断 → 若用户需要根节点作默认，改动仅在一处校验；记为 Open Question。
- 类型码映射硬编码 4 种 → 新增成本类型需改码表；本期接受，未来随科目映射一起做成字典。
- 停用父节点阻断可能让用户觉得繁琐 → 优于静默断链，且与规格撤销阻断（行 804）精神一致。

## Migration Plan
新增迁移 `011-mdm-cost-center.sql`（`CREATE TABLE IF NOT EXISTS`），种子 1 条示例：`CC-PROD-01`（根节点，挂 `le-0001`）。只增不改，回滚即删表。
